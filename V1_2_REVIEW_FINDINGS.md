# v1.2 acceptance review findings

Scope: supplement sections 6.7–11 against the existing uncommitted v1.2 implementation on `review/tizen-compatibility-correctness-1.1`, base `b5fe963`. Original work is preserved. This is checker review with synthetic evidence, not product certification. Earlier M1–M4 observations remain in [V1_2_VALIDATION.md](V1_2_VALIDATION.md).

| Finding | Correction | Production evidence / regression |
|---|---|---|
| Two root consumers reaching the same transitive failure could receive identical finding IDs. Finalization retained only the last root context. | Include root/consumer/provider context in linker finding identity. Exact duplicates are counted in `occurrences`; conflicting ID payloads are rejected. Reports expose `finding_integrity`. | `linker.dependency_checks`, `compare.finalize`; `AcceptanceTests.test_two_root_consumers_keep_distinct_transitive_evidence`, `test_duplicate_findings_are_audited_and_conflicts_rejected` |
| Manifest reuse skipped reconciliation when the expected-test list was absent, allowing old successful cell checks to retain completeness credit. | Always reconcile; absent plans cannot pass. Unplanned positive tests become UNKNOWN. Preserve unplanned/recorded failures as PARTIAL. | CLI manifest reuse branch, `matrix_manifest.reconcile`; `test_v12_manifest_without_expected_metadata_cannot_reuse_pass`, `test_unexpected_failure_and_legacy_matrix_failure_remain_visible` |
| Global status and compatibility gate depended primarily on finding rows; a failing recorded obligation without a finding could be missed. | Global status includes confirmed coverage/test/package failures. Orphan obligation failures have explicit gate reasons, default HIGH severity subject to `fail_on`. | `coverage.coverage_report`, `report.build_results`; `test_obligation_failure_without_finding_controls_global_status_and_gate` |
| Data-only packages could aggregate metadata equality into overall COMPATIBLE despite all interface dimensions being N/A. | Complete inventory can establish NOT_APPLICABLE; it cannot manufacture a public-interface pass. Incomplete applicability remains UNKNOWN. | `package_analysis.analyze_packages`; `test_data_only_overall_is_not_a_compatibility_pass` |
| No explicit provider-package → consumer-package report index; candidate packages were represented only by matching/addition metadata. | Add indexed dependency edges, path/dimension finding relationships, and a candidate assessment for every candidate identity. | Required small package examples, capability categories, production prerequisites and exact acceptance mapping were absent. | Add generated package reports, remediation/capability document, and final acceptance/test matrix. | [package example](.agents/skills/tizen-image-compatibility/examples/package-report/README.md), [remediation](V1_2_CORRECTNESS_REMEDIATION.md), [validation](V1_2_VALIDATION.md) |

During the new tests, one assertion incorrectly expected missing library *path alone* to prove ABI breakage. Production correctly returned UNKNOWN because relocation/replacement is unresolved. The test now checks that uncertainty and separately confirms a missing dependency under a complete declared loader environment. This was a test expectation correction, not weakened verification. A Counter construction bug in the new serialized-report verifier was also fixed before the final run; failed exploratory output is retained separately from final success logs.

All named `AcceptanceTests` functions are in [test_acceptance.py](.agents/skills/tizen-image-compatibility/tests/test_acceptance.py). The full 20-scenario mapping, execution commands, counts and limitations are in [V1_2_VALIDATION.md](V1_2_VALIDATION.md).
