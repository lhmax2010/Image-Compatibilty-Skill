# Security and side effects

The security review examined the v1.5.1 baseline `2d43c58` and the production-readiness changes. The observations below use local, benign fixtures. The review did not connect to a device, run an image binary, access an external service, or install host software.

## Corrected findings

| Finding | Baseline evidence and trigger | Impact | Correction and verification |
| --- | --- | --- | --- |
| P1 — Interrupted tool evidence | `core.py:352–385,419–428`: Ctrl+C between the pipe read and evidence write drops bytes already consumed. The frozen Runtime controller fixture flushes its output immediately before sending SIGINT. | Intermittent loss of the last observation even though the controller process group was reaped and the interruption recorded. | Defer SIGINT during the short read-and-write operation, then honor interruption. Preserve bounded evidence before propagating interruption. The deterministic `test_interrupt_between_pipe_read_and_evidence_write_preserves_output` failed with empty evidence on the prior implementation and passed after the correction. | P1 — Unbounded default tool capture | `core.py:296–344`: default calls spool unbounded stdout/stderr to disk and make a second evidence copy. ## Side-effect model

- Static analysis invokes configured host parsers with explicit arguments. RPM uses metadata and payload commands, copies an installed RPM database before querying it, and does not install packages or execute scriptlets. RPM CPIO is parsed into a virtual inventory. Archive-controlled hardlinks or symlinks are not materialized by the RPM reader. TAR symlinks are resolved inside the image's virtual root, and special nodes are represented as metadata.
- Static jobs create report, evidence and private scratch files at the requested output. A cache is optional and separate from source. Source content hashes and untouched scriptlet sentinels are checked by the fixture. Host read operations may update input access timestamps depending on mount policy.
- Configured tools, SDK compilers, and vendor filesystem adapters are trusted operator selections. Vendor extraction is an opt-in external host-code boundary. Content receipts bind input and output bytes and do not sandbox an adapter. The standard EROFS path does not mount the image filesystem into the host, use root or access the network.
- Runtime stays explicitly authorized and separate from the default static workflow. SDB targets are individually enrolled and pinned. Actual and target-side observation requirements stay distinct from local process-group cleanup. Evidence for a target directory whose creation or deletion could not be observed remains incomplete. This review did not revalidate hardware.
- Generated HTML escapes report data. Browser report scripts render data fields as text, and the optional HTTP server binds to loopback and checks the Host header. CSV writers guard common spreadsheet formula prefixes. Evidence downloads resolve beneath the selected evidence tree. Treat report text, logs and configuration snippets as data. The report and cache may retain local paths and file excerpts, so use a private output tree and company-approved artifact handling. No automatic upload is present in the static CLI.

## Reproduce

```bash
SKILL=.agents/skills/tizen-image-compatibility
python3 -m unittest discover -s "$SKILL/tests" -p test_framework.py -v
python3 -m unittest discover -s "$SKILL/tests" -p test_frozen_runtime.py -v
python3 -m unittest discover -s "$SKILL/tests" -p test_rpm_payload.py -k confined -v
python3 -m unittest discover -s "$SKILL/tests" -p test_final_release.py -k rootless_adapter -v
```

The focused runs passed all 36 framework and 16 synthetic frozen Runtime cases. The separate EROFS confinement case and two mocked rootless adapter cases passed. Standard `mkfs.erofs` and `fsck.erofs` were unavailable from installed tool locations and the workspace, so no standard or Samsung filesystem was actually extracted.

## Remaining operating boundaries

- Static limits apply to tool output/time, ELF worker concurrency, and archive work. They are not a machine-wide CPU, RSS, process or filesystem quota across concurrent jobs. Use existing company isolation and a resource budget for very large or untrusted inputs. The production capacity claim requires the authorized large VD repository run. Installed-rootfs collection, SquashFS output, vendor adapters and optional indexing do not share one global hard quota.
- Local process-group reaping verifies members of the managed group. Arbitrary daemons that create new sessions require an independent cgroup/sandbox authority. Do not configure untrusted executables as tools.
- Live input or report trees shared with untrusted writers fall outside the stable-input model. Use distinct private task outputs, account-owned cache roots and immutable input snapshots. Generated evidence can contain host paths or sensitive input text even when no remote operation occurred.
- Real EROFS decoding, vendor format compatibility, actual device supervision and internal distribution controls require their own environment evidence. The synthetic acceptance does not close those gates.
