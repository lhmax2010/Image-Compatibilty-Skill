# 跨报告回归

仅接受经过验证的增强报告，要求显式写明匹配产品谱系和方向，并核对两侧记录的架构。优先配对相同 ID、相同原 payload 摘要和相同上下文。只有两次报告里都唯一的启动依赖检查，且两侧原 payload 的 baseline 契约及检测方法一致，才允许匹配不同 ID。所有其他差异保持不匹配并保存原因和原 ID。

历史状态有新增、已修复、持续、证据加强／退化、状态变化和未证实消失。修复要求匹配的 INCOMPATIBLE 到已观察的正结果。消失、不同 Provider 名称或新增 UNKNOWN 均无修复信用。报告保留原覆盖分母与结果，证据变化以两次报告记录的可追溯状态为据。

合成正反对照包含一条确证修复、一条引入破坏、持续 UNKNOWN、同名歧义及无确认的消失项。历史真实数据的自身对照用于验证全量身份与分页，实际产品风险演进需要第二套独立、同范围的采集结果。

真实历史身份控制在 898342 个原 ID 上取得 898342 项 `EXACT_ID_AND_PAYLOAD`，其中 872305 项持续风险、26037 项其他不变记录，证据状态和覆盖分布均一致。独立脚本逐行核对原 CSV、历史 SQLite 和历史 CSV。正反合成对照的 `--fail-on introduced` 确认返回 1 并保留完整发布报告。
