# 性能实测

| 真实 ARM 既有索引，同一输入 | v1.4 RC 历史 | 最终实现 |
|---|---:|---:|
| 端到端 | 848.382 s | 350.539 s |
| 对账 | 431.320 s | 68.901 s |
| 源内容摘要 | 213.292 s | 81.872 s |
| SQLite | 489259008 B | 489259008 B |

主要瓶颈为机械盘上的随机页读取。SQLite 默认按子表顺序扫描外键，与另一端的主键顺序不一致。最终实现按被引用键检查各关系，保留正式外键约束、独立完整性检查、原状态和成员对账。历史组核对按旧组索引排序，源角色验证用已核对的侧车 ledger 避免再随机访问旧 Findings。两次输出逐字节相同。

实测处于 720 s 预算内。源摘要冷热差异独立列出。新旧测试均在本机 ext4 机械盘执行，未清空系统页缓存；单机一次完整读数不会证明参考 SSD 上的冷缓存、最坏时延或重复性能。独立浏览器和 HTTP 测量见验收回执。

本轮侧车进程树峰值约 170.15 MiB。组摘要加首批成员 p95 为 60.990 ms，包首批组 p95 为 103.694 ms，各 100 次 HTTP 热样本。历史原样对照耗时 439.365 s，SQLite 1215348736 B，CSV 284342993 B。独立历史查询命中变更与序号索引。

带 sandbox 的 Chrome 在合成联合报告验证了历史首屏、下一页、确认新增筛选、编译／运行页和影响组到证据访问。测得操作分别约 2475、83、83、95、534 ms，记录 0 个 JavaScript 异常及 0 次完整 SQLite/JSON 下载。实际规模报告的查询由单独的真实 HTTP 验收计时。
